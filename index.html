1. סקירה כללית ותצורת מערכת (System Overview)

                            Single-File SPA + Serverless Proxy
                        

                        

                            AutoGit היא פלטפורמת Self-Hosted / Serverless להקמה וניהול אוטומטי של אפליקציות Full-Stack על גבי GitHub ו-Cloudflare Workers ללא שרת מסורתי וללא בסיס נתונים חיצוני. המערכת בנויה מקובץ ממשק יחיד (index.html) המתקשר מול GitHub REST API ומול Cloudflare Worker (worker.js) הפועל כ-GitHub App Proxy.
                        

                        

                            

                                
Control Plane (Studio)

                                
GitHub_Automation_Studio_Frontend

                                
ממשק הניהול הראשי (SPA) הכולל את הכדור האינטראקטיבי, ניהול מאגרים, כינויים, פאלטות ודיאגנוסטיקה.

                            

                            

                                
Private State Store

                                
GitHub_Automation_Studio_Backend

                                
מאגר פרטי השומר את .studio-config.json (כתובת Worker, תבניות, פאלטות וכינויי מאגרים) ואת README.md.

                            

                            

                                
Provisioned App Pair

                                
{slug}_Backend + {slug}_Frontend

                                
כל אפליקציה מוקמת כזוג מאגרים: פרטי (data.json כ-DB) ופומבי (GitHub Pages עם SALTED_VAULT מוצפן).

                            

                        

                    


                    
                    

                        
2. תהליך הקמת אפליקציה (Hybrid Provisioning Pipeline)

                        

                            

                                
שלב א׳ — זיהוי, מזהה וגזירת מפתח (Slug & SHA-256)

                                
המשתמש מזין סיסמת אפליקציה. המערכת מייצרת מזהה אקראי בן 11 תווים ({slug}) ומחשבת חתימת SHA-256("{owner}/{slug}::{password}").

                            

                            

                                
שלב ב׳ — שכפול עץ אטומי (Atomic Git Tree Clone)

                                
ה-Worker מנפיק Installation Token קצר-מועד וקורא רקורסיבית את עץ הקבצים מ-_Template_Backend ומ-_Template_Frontend, ויוצר Commit יחיד נקי בכל מאגר.

                            

                            

                                
שלב ג׳ — הצפנת קצה-לקצה (PBKDF2 + AES-GCM)

                                
כתובת ה-API של ה-Backend (https://{worker}/{owner}/{slug}_Backend) מוצפנת בדפדפן באמצעות PBKDF2 (100,000 iterations) + AES-GCM 256-bit ומוזרקת לתוך SALTED_VAULT ב-index.html.

                            

                            

                                
שלב ד׳ — פריסה אוטומטית (GitHub Pages)

                                
לאחר השהיית Jitter למניעת Rate-Limit, המערכת מפעילה אוטומטית GitHub Pages על ענף main עבור מאגר ה-Frontend ומאמתת זמינות חיה (200 OK).

                            

                        

                    


                    
                    

                        

                            
3. מסלולי Cloudflare Worker API

                            

                                

                                    GET /ping
                                    
בדיקת תקינות השרת והחזרת cfRay.

                                

                                

                                    GET /gh-app-status/:owner
                                    
אימות התקנת ה-GitHub App ושליפת installationId.

                                

                                

                                    POST /gh-clone-tree
                                    
שכפול אטומי של מאגרי תבנית דרך Git Trees API.

                                

                                

                                    GET & POST /:owner/:repo
                                    
קריאה וכתיבה ישירה של data.json במאגר הפרטי עם Scoped Token.

                                

                            

                        


                        

                            
4. תצורות ומצבי המערכת (Modes & Config)

                            
    
                                
  • 
                                    מצב אורח / נעול (initial / awake): כל הטאבים והגדרות התשתית מטושטשים (blur-md) וה-PAT אינו נשמר בשרת. לחיצה על הכדור פותחת הזנת טוקן מהירה.
                                
    • 
                                
  • 
                                    מצב מחובר (ready / building / success / error): סנכרון דו-כיווני מול .studio-config.json — כולל פאלטות צבעים מותאמות, כינויי פרויקטים (repoAliases) וכתובת Worker.
                                
    • 
                                
  • 
                                    ניהול מאגרים חכם: בדיקת סטטוס חי (200 / 404) עם מיני-כדור, עריכת data.json ישירה, העתקת סניפט Salted ל-AI, ומחיקת מאגר בודד או זוג מלא.
